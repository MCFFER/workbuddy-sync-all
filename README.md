# workbuddy-sync-all

> 把你名下多台电脑上的 AI 编成一支小队：共享技能与配置、互相派活、接力交付。

一个 WorkBuddy skill，通过同步协作空间共享文件与日志，解决一个很具体的问题：
**同一个人在几台电脑上各有一个 WorkBuddy，切换电脑时不知道另一台的 AI 做到哪了。**

---

## 它解决什么问题

- 你在办公室、家里不同电脑上的工作，可以由 AI 无缝衔接
- 在一台机器上做到一半，换到另外一台机器上接着做，AI 不知道前情
- 在不同的电脑上装上这个，你仿佛有了一个AI工作小组，工作小组之间互通有无，互相知道对方在干什么，也可以接力对方的活。
- 该协同机制无需架设服务器，通过本地同步文件夹，共享文档、共享记忆、协作沟通。
- 本 skill 目前只支持 WorkBuddy：各机登录同一账号，按本目录说明完成同步即可。

这些都不是模型能力问题，是**协作基础设施问题**。

## 六道机制

| # | 机制 | 做法 |
|---|---|---|
| ① | **防碰撞** | 同机多对话：编辑锁 + 写护栏（钩子硬拦）；跨机：文件预约 + `fence` 序号 |
| ② | **防误删** | 同步夹开版本控制，删除进 `.stversions` 保留 30 天可找回 |
| ③ | **预演练** | 加机器 / 迁移 / 卸载一律默认 dry-run，`--apply` 才执行 |
| ④ | **免服务器安装** | 首次连接走免费公共中继 + 局域网，不需要自建服务器或交换设备 ID |
| ⑤ | **增量省流** | 读对端记忆按游标增量，不整份读；状态卡片 ≤10 行 |
| ⑥ | **无痕退出** | `uninstall` 两阶段：先在同步开启时清理并确认送达，再脱组；对端 `prune` 收尾 |

## 架构

```
      ┌─────────┐        ┌─────────┐        ┌─────────┐
      │  A 机   │        │  B 机   │        │  C 机   │
      └────┬────┘        └────┬────┘        └────┬────┘
           └──────────────────┼──────────────────┘
                  Syncthing（5 个同步夹 · P2P · 无中心）
                              │
      ┌───────────────────────┴────────────────────────┐
      │  coop/            协作通道                    │
      │    · A2A 任务单（带回执状态机）                │
      │    · 专线记事本（长正文）                      │
      │  <后缀>/memory/   各机私有记忆与日志           │
      │     · MEMORY-<后缀>.md   长期记忆              │
      │     · YYYY-MM-DD-<后缀>.md  每日日志           │
      │     · STATE-<后缀>.md    状态卡片              │
      └────────────────────────────────────────────────┘
```

每台机器只写自己后缀的目录，别人只读——**归属靠命名，不靠权限位**（权限位会挡住同步写入）。

## 快速开始

1. 把本目录放到 `~/.workbuddy/skills/workbuddy-sync-all/`
2. 在对话里说「开始同步」触发 skill
3. `wbsync workspace init` 建协作区（默认只演练，加 `--apply` 执行）
4. 第二台机器重复 1–3，走 `wbsync probe` 拿编号 → 配对 → 共享同步夹
5. 每台机器跑一次 `wbsync guard on --apply`（开版本控制兜底）

之后日常只用一条：`wbsync wake`。

## 常用命令

| 命令 | 作用 |
|---|---|
| `wbsync wake` | 一条命令看全：本机身份 / 同步健康 / A2A 待办 / 未读 / 对端状态 |
| `wbsync a2a send` | 派活，带 submitted → working → completed 回执闭环 |
| `wbsync a2a check` | 看别人派给我的活 |
| `wbsync mem index` / `mem read` | 看对端记忆索引 / 增量读日志 |
| `wbsync reserve claim` | 跨机文件预约（改共享文件前） |
| `wbsync lock claim` | 同机多对话编辑锁 |
| `wbsync uninstall` | 干净退出协作组 |

完整命令表与参数见 [`references/commands.md`](references/commands.md)。

## 设计取舍

- **纯文本，不用数据库**：坏了能手修、能 `grep`、能 `git diff`；不需要为备份再搭一套
- **无服务器、无账号**：不依赖任何云端，机器之间直连
- **归属靠约定**：各机只写自己目录；并发靠预约锁与写护栏，而不是靠人记得
- **默认演练**：所有破坏性操作都要 `--apply`，先看它打算干什么

## 跑测试

```bash
python3 tests/test_wbsync.py              # 全量（800+ 项，约 1 分钟）
python3 tests/test_wbsync.py --list       # 列出章节号
python3 tests/test_wbsync.py --section 12 # 只跑某几节
```

> ⚠️ **有副作用**：少数测试节会读取、并尝试写入本机 WorkBuddy 的真实配置
> （`~/.workbuddy/workbuddy.db`、看板锁文件 `coop/shared/board/.render-lock`）。
> 在别人的机器上跑全量前，**先备份或先看 `--list` 只挑代码逻辑相关的节**。
> 这部分是历史遗留的测试设计问题，欢迎 PR 改成纯临时目录。

## 平台

macOS / Windows / Linux。Windows 上由 `scripts/wbsync.cmd` 提供入口。

## 已知限制

- 依赖 Syncthing 做传输层（首次使用会自动下载官方二进制）
- 同步是准实时而非真实时：删了要等传播，离线对端上线后才收到
- 同机多对话靠平台注入的 session id 区分；拿不到时会退化到「按工作目录 + 缓存」，同目录并行可能互相认错（见 `references/troubleshooting.md`）
- 冲突副本（`*.sync-conflict-*`）只保证不丢，不保证可用，出现即说明前两层漏了
