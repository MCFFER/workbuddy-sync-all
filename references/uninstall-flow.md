# 参考：对话式退出 / 卸载（自然语言流程）

> 用户用**自然语言**表达「退出 / 卸载 / 离开协作组」时，AI 照本流程走。
> **铁律：先演练、说清后果、请用户确认、再执行；绝不先 `--apply`。**

## 触发语

「退出」「退出同步」「卸载（这个同步）」「不玩了」「离开协作组」「把 X 机移除 / 踢掉」「这台机器不用了」……
以及任何用户想让某台机器**停止参与多机同步**的说法。

## 四条铁律

1. **发起权限**：退出**只能由 A 机（主节点）或本机发起**。用户若在本机（如 B）上要求「把 C 踢掉」→ **拒绝**并解释（B 无权踢 C；请 C 自己退出，或由 A 发起）。
2. **先演练后执行**：第一步永远跑**不带 `--apply`** 的演练（只读），拿到「将会发生什么」再谈执行。
3. **说清传播语义**：删除本机在协作区的东西，**会同步到其他机器**，把它们上面的该机内容也清掉；对端自己写的文件不受影响。
4. **必问日志留存**：一定要问用户「长期记忆 / 工作日志**要不要留在其他机器上**」。

## 步骤

### 1. 只读演练

```bash
wbsync uninstall            # 默认演练；本机发起
wbsync uninstall --by A     # A 机远程委派别人退出（发起者=A）
```

拿到输出里的清单：对端、将删的本机产物、记忆/日志、资料库登记、将停的服务。

### 2. 用自然语言把「会发生什么」讲给用户

照下面的模板（按实际清单填），**不要只贴命令输出**：

> 「**X 机**要退出协作组，会发生这些事：
> - **停用同步并卸载 Syncthing**：X 机不再与其它机器同步。
> - **删除 X 机在协作区的东西**（X 的私有区 / 专线 / 能力卡）。**注意：这些删除会同步到其他机器**，把它们上面的 X 的内容也一起清掉；其它机器自己写的文件**不受影响**。
> - **广播退出通知**给其它机器（A2A + 记事本）。
> - **资料库里的「X 机设备登记」**会被**移入「已退出机器登记」归档子文件夹**——资料库没有删除接口，但可以 `move-node`「移走」，从主登记里清出去。这个归档子文件夹由 skill **自动建好**（首次 init 时，走 `nodeKind=folder` 建在「多机同步登记（勿删）」下，名叫「已退出机器登记」），无需你手动建。
> - **登记退役**：X 机记入退役（第 1 代），若以后有新机器顶替 X，会记为第 2 代，历史里可分辨。
> - ⚠️ **不可逆**：要重新加入得重跑安装 / 配对，且设备 ID 会变。」

### 3. 请用户确认或取消

> 「确认执行吗？（**确认** / **取消**）」

- **取消** → 什么都不做（演练本就是只读），结束。
- **确认** → 进入第 4 步。

### 4. 问日志留存（核心问题）

> 「你的**长期记忆和工作日志**（N 个文件）——**要不要留在其他机器上**？
> - **留**：归档到协作共享区（`_退出归档-X-genN-日期/`），其他机器能看到、能查阅。
> - **不留**：一并删掉（本机也不留）。
> 默认**留**。」

用户答「留 / 保留」→ `archive`；答「删 / 不留」→ `delete`。

### 5. 执行（命令内部是「两阶段」，无需用户关心）

```bash
wbsync uninstall --apply --memory archive     # 留
wbsync uninstall --apply --memory delete      # 不留
wbsync uninstall --apply --memory archive --by A   # A 委派场景
```

> 命令内部顺序（**两阶段**）：**阶段一**（同步仍开启）发通知 → 归档/删记忆 → 清本机在协作区的产物（删除会传播到其他机器）→ **等送达**；**阶段二**（本机收尾）注销 hook 并移走脚本 → 停同步脱组 → 资料库登记 doc 移入归档 → 清本地基础设施 → **收尾自检**。
> 这个顺序的道理：**凡是需要「传播出去」的动作，都必须赶在断掉同步之前完成并确认送达**——否则删除/归档只落在本机，其他机器同步不到，等于没做。

### 6. 播报结果

执行后本机同步会**停掉，可能无法回传结果**——告知用户：

> 「X 机已完成退出：已停用同步、清理本机在协作区的内容、登记退役。**收尾已自检**（hook 已注销、脚本已移走、引擎已停）。因为同步已停，其它机器不会再收到本机的新消息；请 A / B 收到退出通知后，各自跑 `wbsync prune --peer X --apply` 完成本机侧收尾。」

## 对端侧收尾（收到他机退出通知后）

退出机只能清自己、并发通知；**设备表条目在每台机本地，远程改不了**。所以各机收到退出通知后，跑：

```bash
wbsync prune --peer C            # 演练（只读）
wbsync prune --peer C --apply    # 清理：协作区残留 + 登记表退役 + 移除设备表/各夹授权
```

要点：
- **幂等**：已经清过再跑会提示「未发现 C 机的任何痕迹」。
- 若退出机的删除因对端离线没送达，`prune` 会把残留**兜底**删掉（同步态删除 → 再传播给其他对端）。
- 设备表移除**必须每台机各做一次**（不跟随同步传播）。

## 用户只在某台机上、要退另一台

- **在 A 机**要求退 C → 合法：A 发起，`--by A`。可发 A2A 任务让 C 执行，或直接在 C 上执行。
- **在 B 机**要求退 C → **拒绝**（B 无权）。回：请 C 自己退出，或由 A 发起。
- **本机退自己** → 直接 `wbsync uninstall`（默认发起者=本机）。

## 常见追问

- 「会不会把我别的机器的文件删了？」→ 不会。只删**本机做的**；对端自己写的文件不在删除范围。但本机做的东西**会**在别的机器上被清掉（这正是要的效果）。
- 「退出后还能回来吗？」→ 能，但要重跑安装 / 配对，且设备 ID 会变（登记表按世代区分新身份）。
- 「日志留在其他机器上安全吗？」→ 归档目录是共享区普通文件，其他机器可读；按需选「不留」。

## 踩坑清单（2026-10-14 C 机退出实战沉淀，每坑都已在代码层修掉）

> 这是**首次真实退出**暴露的问题，后续退出前应逐条对照，确认代码版本 ≥ 2.7.4（含所有修复）。

| 坑 | 现象 | 根因 | 修复（版本） |
|---|---|---|---|
| **P0-1 删除/归档没传出去** | A/B 上看不到 C 的退出归档、C 的残留还在 | 「归档/删除」与「停同步」同流程内先后执行，写盘后没留送达窗口，引擎即停 → 变更没宣布出去 | `_uninstall_wait_delivery` 改为 rescan + 本机 idle + 在线对端 completion=100 + 宽限（v2.7.2） |
| **P0-2 退出没"粘住"** | 退出后会话一开，引擎又自启并**生成全新 deviceID**（幽灵实例） | uninstall「停 hook」只改 settings.json 注册，**hook 脚本本体还在**；又因配置已清 → 引擎重新生成默认配置+新证书 | 移走 hook 脚本（软注销）+ 收尾自检 + 清配置守卫（v2.7.3） |
| **P1-1 重跑报错像失败** | 再跑一次 `uninstall` 报「无法确定本机后缀」 | 入口依赖引擎取后缀，引擎已停 → 取不到 → 硬失败 | 入口幂等：落 `.wbsync-exited.json` 退出标记，重跑提示「已退出」（v2.7.3） |
| **P1-2 删除无回执** | 不知道删除到底传没传到对端 | 同 P0-1 | 同 P0-1 的送达确认 |
| **P2-1 暂存位置不可发现** | 回收站不可用时，删掉的东西不知道去哪了 | 未打印降级暂存位置 | 结束时打印暂存位置 + 恢复方法（v2.7.3） |
| **P2-2 资料库登记删不掉** | 「C 机设备登记」doc 无法删除 | 资料库无删除节点 API | 改用 move-node「移入归档子文件夹」，子文件夹由 skill 自动建（v2.7.4 / 2.7.6） |
| **资料库重命名"假成功"** | 标记了却没变 | rename-node 多传 space_id 导致静默失败 + 不检查返回 | 去 space_id + 检查返回（v2.7.3） |
| **重接入旧数据复活** | C 退出后本地 `sync-all-C` 还在，重接入会把它当新增推回 A/B | 无「已退出重接入」检测 | 退出时封存工作空间 + 重接入防护（v2.7.5 计划） |

## 执行后的核对清单（退出机自己核一遍）

1. **送达**：退出通知、归档、删除是否已在对端可见（对端 `wbsync wake` 能看到）。
2. **脱组**：本机 Syncthing 进程已停、`wbsync stop` 不再报「在运行」。
3. **hook 干净**：`wbsync hook status` 显示 SessionStart 未写入；`~/.workbuddy/scripts/wbsync-autostart-hook.sh` 已不在。
4. **无幽灵实例**：重启 WorkBuddy 后 Syncthing 不再自启（`wbsync status` 显示未运行）。
5. **幂等**：再跑 `wbsync uninstall` 应提示「已退出」，而非报错。
6. **登记退役**：对端登记表里本机已移入 `retired`（带世代 + deviceID）。
7. **资料库**：本机登记 doc 已移入「已退出机器登记」或已重命名标记。
